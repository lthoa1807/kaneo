A workspace contains members, projects, and shared labels. Use one workspace for people who should work together. Create separate workspaces when access needs to stay separate.

Projects divide the work inside a workspace. A website launch, a support queue, and an internal roadmap can each be a project.

## Create a workspace

Use the workspace menu at the top of the sidebar to create a workspace. Give it a name your teammates will recognize. You become its owner.

If you received an invitation, accept it instead of creating another workspace for the same team.

## Create a project

1. Switch to the right workspace.
2. Choose **Add project** in the sidebar, or create one from **Projects**.
3. Enter its name and submit the form.
4. Open the project from the sidebar.

## Choose a view

Switch between **Tasks** and **Backlog** at the top of a project. Inside **Tasks**, choose a layout from **Display**.

| View | Use it for |
| --- | --- |
| Backlog | Preparing work that is not ready to start |
| Board | Moving tasks through status columns |
| List | Scanning task properties in rows |
| Calendar | Reviewing tasks by date |
| Gantt | Seeing scheduled work across a timeline |

Changing views does not create a second copy of a task.

## Track project details

Workspace admins define project fields in **Settings → Workspace → Project fields**. Each field has a type: text, long text, number, date, dropdown, multi-select, yes/no, or formula. Formulas only read other project fields, so they stay up to date and are never edited directly.

Each project stores its own values. Open a project and use **Settings → General** to fill them in, or open **Projects → Fields** to compare values across projects, filter and sort them, and export the table as CSV. Values are saved as you edit them.

Project fields are separate from task custom fields. Use project fields for details that belong to the whole project, such as a client, a budget, or a target launch date.

## Change settings

Open **Settings → Projects** and select your project to manage its details, workflow, and integrations. Workspace settings hold shared details, labels, and roles.

The controls you see depend on your permissions. If you cannot create a project or change its settings, ask a workspace admin to check your role.

**Settings → General** also holds **Accept guest requests**. Turn it on to let people outside the workspace send you requests on this project, and turn it off without deleting the requests already made. See [guest requests](/core/functional/guest-requests).
